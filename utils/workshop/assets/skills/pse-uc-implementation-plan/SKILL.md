# CoCo Use Case Deep-Dive Report Generator

Generate a detailed, developer-oriented solution guide for a specific Snowflake use case — similar to the ONSemi Semantic Layer Solution Guide and Clarios OpenFlow Reassessment Technical Response.

## EXTERNAL SHARING RULES (MANDATORY — applies to ALL generated reports)

Reports generated by this skill are **external-facing** and shared with partners and customers. These rules are based on the **Snowflake Legal "Guidelines for Sharing Customer Information with Partners"** (Last Updated: October 2, 2026).

### PRE-CHECK: Red Light List (REQUIRED before generating ANY report)
Before generating a report for any account, you MUST check the Red Light List:
```sql
SELECT * FROM SNOWHOUSE.IT.RAW_GOOGLE_SHEETS.TOP_SNOWFLAKE_COMPANIES
WHERE COMPANY_NAME ILIKE '%<ACCOUNT_NAME>%';
```
If the account appears on the Red Light List, **STOP IMMEDIATELY**. Do not generate the report. Inform the user:
> "This account is on the Red Light List. Per Snowflake Legal guidelines, no information about this customer may be shared with external partners, regardless of NDA status."

### WHAT YOU CAN INCLUDE (per Legal guidelines):
1. **Customer name** — that they are a Snowflake customer (unless Red Light List)
2. **Partner name** — the implementation partner (they know who they are)
3. **Use case name** — the Name__c field from Salesforce
4. **Problem statement** — rewritten from Description__c using ONLY publicly available facts (never verbatim)
5. **Snowflake solution architecture** — this is Snowflake's own product information
6. **SQL patterns and implementation steps** — Snowflake product documentation
7. **Documentation links and quickstarts** — public Snowflake resources
8. **CoCo skills mapping** — Snowflake's own product capabilities

### WHAT YOU MUST NOT INCLUDE IN THE REPORT (even if available in Salesforce):
1. **No people's names** — no SE names, no partner contact names, no customer contact names
2. **No SE/Partner/Manager/Specialist comments** — internal Snowflake confidential
3. **No MEDDPICC fields verbatim** — pain points, metrics, decision criteria, decision process
4. **No contract details** — no EACV, no pricing, no capacity commitments
5. **No consumption metrics** — no credit usage, no warehouse spend
6. **No UC numbers or SFDC links** — internal system identifiers
7. **No internal Snowflake strategy** — no co-investment, funding, RFP details
8. **No competitor intelligence** — do not name competitors
9. **No internal Google Doc / Slack / Email links** — internal artifacts
10. **No customer data or business plans** — anything disclosed in confidence
11. **No commercial relationship details** — what they're paying, renewal plans
12. **No industry vertical** — do not include Account__r.Industry (e.g., "Industrial Goods", "Media & Streaming")
13. **No country/state/location** — do not include BillingCountry, BillingState (e.g., "United States", "Wisconsin", "Canada")
14. **No website** — do not include Account__r.Website (e.g., "clarios.com")
15. **No pipeline stage** — do not include Stage__c (e.g., "Deployed", "Implementation In Progress")

### HOW to use internal data (use it to understand, don't expose it):
- **SE Comments** → Read to understand the technical situation. Synthesize into a neutral architecture recommendation without quoting.
- **Partner Comments** → Read to understand partner engagement. Tailor the solution but do not quote.
- **MEDDPICC Pain** → Read to understand the real business pain. Rewrite as a clean "Problem Statement" using ONLY publicly available facts about the customer (public filings, press releases, website info).
- **MEDDPICC Metrics** → Read to understand scale. Include metrics ONLY if they are publicly available (e.g., number of manufacturing sites from a press release). NEVER include metrics from confidential discussions.
- **MEDDPICC Decision Criteria** → Read to understand what matters. Structure the solution around these criteria without quoting them.
- **Competitors__c** → Read to understand the landscape. Position Snowflake on its own merit without naming competitors.
- **Risk fields** → Read to understand risks. Address as "architecture considerations" without quoting the risk assessment.
- **Consumption/contract data** → NEVER include. Not even aggregated or approximated.

### Report header format (external-safe):
```
Account: <Account__r.Name from Salesforce>
Use Case: <Name__c from Salesforce — strip the account prefix if duplicated>
Prepared for: <Account Name> / <Partner Name>
Prepared by: Snowflake Partner Solutions Engineering
Date: <Date>
```
The Account and Use Case Name fields must be pulled exactly from Salesforce `Account__r.Name` and `Name__c`.
Do NOT include: UC number, EACV, Stage, Salesforce metadata, or Snowflake personnel names.

### Sharing Method Reminder (per Legal guidelines):
- Share via **Google Drive with named individuals only** (no open links, no attachments)
- Or via **Crossbeam** if available
- Revoke access when the engagement is complete
- Maintain a record of what was shared, with whom, and when

## MODES

This skill has four modes:

### Mode 1: Single Use Case (default)
Generate a deep-dive solution guide for ONE use case. User provides a UC number, SFDC link, or use case name.

### Mode 1A: Multiple Use Cases
Generate deep-dive solution guides for a LIST of use cases. User provides multiple UC numbers, SFDC links, or use case names (comma-separated or one per line). This mode:
1. Pulls Salesforce data for each UC
2. Checks Red Light List for all accounts
3. Generates HTML + DOCX for each
4. Zips all reports together
5. Creates a single Gmail draft with all reports listed
6. Creates Google Drive folder(s)

**Trigger**: User provides multiple UC numbers (e.g., `UC-029904, UC-004380, UC-016101`) or says "generate for these use cases".

**Naming**: Each report is named `<AccountName>_<ShortUseCaseName>_Solution_Guide.html/.docx`. The zip is `CoCo_Deep_Dive_Solution_Guides.zip`.

### Mode 2: Batch (from PSE CoCo Report)
Generate deep-dive solution guides for ALL use cases in a PSE CoCo Report. This mode:
1. Reads the PSE CoCo Report (PDF or JSON from `pse-uc-portfolio-analysis`)
2. Extracts all use cases listed (both CoCo-attached and non-CoCo gap opportunities)
3. For each use case: pulls Salesforce data, researches capabilities, generates HTML + DOCX
4. Uploads all reports to a Google Drive folder
5. Produces an updated summary with clickable "Deep Dive" links next to each use case

**Trigger for batch mode**: User says "batch", "generate for all", "run for the whole report", provides a PSE CoCo Report PDF, or references the `pse-uc-portfolio-analysis` output.

### Use Case Selection Logic (applies to Mode 1A, Mode 2, and partner-name queries)

When selecting use cases for a partner or date range, use the **OKR dashboard logic** from `TEMP.COCO_PARTNER_ADOPTION.V_OKR_USE_CASES_COCO_FINAL`:

```sql
-- Use cases with Decision Date OR Go-Live Date in the selected range
SELECT Name, Name__c, Account__r.Name, Technical_Use_Case__c,
       Stage__c, Decision_Date__c, Go_Live_Date__c
FROM Use_Case__c
WHERE Partners__r.Name LIKE '%<PARTNER_NAME>%'
  AND (
    -- Stages 1-4 (Discovery → Won): filter by DECISION DATE
    (Stage__c IN (
      '1 - Discovery / Evaluation',
      '2 - Proof of Concept',
      '3 - Technical / Business Validation',
      '4 - Use Case Won / Migration Plan'
    ) AND Decision_Date__c >= '<range_start>' AND Decision_Date__c <= '<range_end>')
    OR
    -- Stages 5-7 (Implementation → Deployed): filter by GO-LIVE DATE
    (Stage__c IN (
      '5 - Implementation In Progress',
      '6 - Implementation Complete',
      '7 - Deployed'
    ) AND Actual_Go_Live_Date__c >= '<range_start>' AND Actual_Go_Live_Date__c <= '<range_end>')
  )
ORDER BY Stage__c, Decision_Date__c
```

**Default range:** Current quarter (e.g., Q3 FY27 = Aug 1 - Oct 31, 2026). User can override with "this year", "next quarter", or specific dates.

**Stage → Date Field mapping:**
| Stage | Date Field | Requirement |
|---|---|---|
| 1-4 (Discovery to Won) | Decision_Date__c | Within selected date range |
| 5-7 (Implementation to Deployed) | Actual_Go_Live_Date__c | Within selected date range |
| 0 (Not In Pursuit), 8 (Lost) | — | Always excluded |

### Mode 3: Problem Statement (no Salesforce use case)
Generate a solution guide from a free-form problem statement. No UC number, no SFDC link — just a description of what the customer/partner needs. This mode:
1. Accepts a problem statement + optional customer name and partner name
2. Skips the Salesforce lookup entirely
3. Researches Snowflake capabilities from docs, quickstarts, GitHub, Compass
4. Generates a focused solution guide with implementation steps, SQL, and documentation

**Trigger for problem statement mode**: User describes a problem without providing a UC number or SFDC link (e.g., "how do we monitor Dynamic Tables for Shake Shack?" or "build a solution guide for SAP ingestion into Snowflake").

## PROBLEM STATEMENT MODE WORKFLOW

### PS Step 1: Accept Problem Statement
The user provides:
- **Problem statement** (required) — what they need solved
- **Customer name** (optional) — if provided, check Red Light List before generating
- **Partner name** (optional) — for the report header
- **Additional context** (optional) — the user can add their own knowledge about the account, current tech stack, constraints, etc.

If a customer name is provided, run the Red Light List check. If the customer is on the list, stop.

If a customer name is provided AND the user wants Salesforce context, optionally query:
```soql
SELECT Account__r.Name, Account__r.Industry, Account__r.BillingCountry
FROM Use_Case__c
WHERE Account__r.Name LIKE '%<CUSTOMER_NAME>%'
LIMIT 1
```
Use only the publicly available fields (name, industry, country) — do NOT pull comments or MEDDPICC.

### PS Step 2: Identify Snowflake Capabilities
Parse the problem statement to identify which Snowflake capabilities are relevant. Use the Technical Use Case mapping table AND keyword matching:

| Keywords in problem statement | Snowflake Capabilities |
|---|---|
| monitor, alert, staleness, failure, long-running, email alert, notification | Dynamic Tables monitoring, Alerts, Notification Integrations, DMFs, Event Tables |
| ingest, replicate, CDC, SAP, Oracle, Postgres | OpenFlow, Snowpipe, Snowpipe Streaming, SAP BDC Connect |
| transform, pipeline, ETL, ELT, medallion, bronze/silver/gold | Dynamic Tables, Tasks, Snowpark |
| semantic, metric, BI, report, Tableau, Power BI | Semantic Views, Cortex Agent, SV Autopilot |
| AI, agent, NL query, chat, conversational | Cortex Agent, Cortex Search, AI Functions |
| govern, classify, mask, lineage, PII, compliance | Horizon Catalog, Data Governance, AI Guardrails |
| cost, budget, spend, optimize, attribution | Cost Intelligence, Budgets, Per-User Quotas |
| share, marketplace, data product, collaborate | Data Sharing, Internal Marketplace, Data Clean Rooms |
| migrate, migration, convert, modernize | Snowflake AIM, SnowConvert, Spark Migration |
| ML, model, forecast, predict, train | Snowpark ML, Model Registry, Feature Store |
| app, dashboard, streamlit | Streamlit, SAR Apps, Native Apps |
| iceberg, lakehouse, external table | Iceberg Tables, Catalog Integrations |

### PS Step 3: Research (same grounding rules as single-UC mode)
For each identified capability:
1. `cortex search docs "<capability>"` — get SQL syntax, feature status, config steps
2. `web_search("site:snowflake.com/en/developers/guides <capability>")` — find quickstarts
3. `web_search("site:github.com/Snowflake-Labs <capability>")` — find reference repos
4. Optionally search Compass for internal content

### PS Step 4: Generate Solution Guide
Generate the report using the same HTML template and DOCX format as single-UC mode, but with a simplified structure:

```
1. PROBLEM STATEMENT
   - What was asked (clean restatement of the user's problem)
   - Customer context (if provided — name, industry only)

2. SOLUTION ARCHITECTURE
   - Recommended Snowflake capabilities
   - Architecture flow
   - Component status table

3. DETAILED IMPLEMENTATION
   - Step-by-step SQL and CLI commands (grounded in docs)
   - Source citations for every SQL block
   - Configuration and setup instructions

4. COCO SKILLS ACCELERATION
   - Which bundled skills help and how

5. QUICKSTART RESOURCES & DOCUMENTATION
   - Verified quickstart links
   - Documentation table
   - GitHub repos (if relevant)

6. RECOMMENDED NEXT STEPS
   - Action items for the implementation team
```

### PS Step 5: Present Results
Same as single-UC mode — show file location, open in browser, ask if refinements are needed.
